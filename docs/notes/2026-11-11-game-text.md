# The game's text, and a mod folder (2026-11-11)

The question: can the subtitles be taken out of the game and translated? They can. This note has where the text is,
its format, how the game finds its updates, and the mod folder that lets a changed file in without touching the game's
folder. It quotes no text of the game's beyond a menu word or two.

## Where the text is

- **Not in the language archives.** `ENGLISH.PSARC`, `MP-ENGLISH.PSARC` and the `TPPS<n>-ENGLISH.PSARC` ones hold
  voice alone: `.L.STREAMS` and `.XVAG`.
- **In `R_LANG_<language>.WAD`.** `RESOURCES.PSARC` has the base game's, `TPPS.PSARC` the multiplayer ones
  (`R_LANG_<language>_MP.WAD`). Each update archive from `TPPS1.PSARC` (1.06) to `TPPS5.PSARC` (1.11) has a
  `.WAD.PATCH` for each of them, and the game takes the newest. 1.12 is the executable alone.
- **Seventeen languages are in the archives:** de, el, en, en-gb, es, es-la, fr, it, ja, ko, nl, pl, pt, pt-br, ru, tr
  and zh. This title shows four: `LANGS_NPUA80918.TXT` names en, fr, pt-br and es-la, with the PS3 system language
  numbers 1, 2, 17 and 21.

## The formats

- **PSARC.** Version 1.4, zlib, 64 KiB blocks, archive flag 2:
  - names are absolute, upper case with a leading slash (`/WAD/PS3_BE/R_LANG_EN.WAD.PATCH`);
  - each entry is keyed by the MD5 of its name as written;
  - entries are sorted by name, and the manifest, entry 0, comes first.
- **WAD.** A run of entries: a 64-byte header (u16 tag, u16 flags, u32 size, a 56-byte name), the data, padding to
  16 bytes. The language WAD holds the text (`MSGS_TXT`), two fonts with their textures (`SMF_0`, `SMF_1`) and
  `ICON0.PNG`.
- **`.WAD.PATCH`.** A u16 version (4), a u16 count, then a (u32 offset, u32 length) pair for each step. An offset with
  bit 31 set takes the bytes from the patch's own data after the pairs, any other from the base WAD. `TPPS5`'s English
  patch:

  | step | from | bytes |
  |---|---|---|
  | 1 | the base, from 0 | 0xD00: the headers before the text |
  | 2 | the patch | 0xCE740: the text and the two fonts |
  | 3 | the base, from 0xBBA20 | 0xC630: `ICON0.PNG` |

  The `_MP` patch has the same data. Only its third step's offset differs, by its own base.
- **`MSGS_TXT`.** UTF-8 with CRLF line ends and a NUL at the end:
  - a first line of four counts;
  - then the entries: a line `*<id>*`, at times with capital letters after it (`*<id>*T`), then the entry's lines.

  | | English, `TPPS5` |
  |---|---|
  | entries | 4,968, ids up to 21,601 |
  | words | ~71,000 |
  | the header | `4974 2865 76 12703` |

  - The second and third counts are exactly the `[[S:` and `[[F:` markers (2,865 and 76).
  - The first and the last are 6 and 9 above the entries and the lines this note counts (4,968 and 12,694). A
    translation that keeps one line for one line leaves all four as they are.
- **Subtitles** are entries whose first line is `[[S:<sound>:<time>]]`: the time is `<from>-<to>` in milliseconds for
  a movie, `*` for a line of the game's own voice. The text follows on the next lines.

  | subtitles | entries | words |
  |---|---|---|
  | the bonus behind-the-scenes videos (`BTS_`) | ~1,450 | ~22,600 |
  | multiplayer (announcer, taunts, lobby) | ~760 | ~3,700 |
  | the story and play | ~650 | ~5,500 |

  The other ~2,100 entries, ~39,000 words, are menus, tutorials, lore, items and trophies. The split is by the sound
  names, so it is approximate.
- **What a translation keeps:** the markers, the button names (`[XButton]`, `[SquareButton]` and the others), the
  values put in (`[statPhysPower]`, `[MPSubject]`), `[*1]`, and `\n`, written as two characters, which breaks a line
  inside one.
- **Fonts.** The English text uses no letter outside ASCII but `ö`, `™` and `®`. A language written with the 26 Latin
  letters needs no font change.

Rebuilt from the text taken out of it, unchanged, each of `TPPS5`'s English patches came back byte for byte.

## How the game finds its updates

- It reads `ARCHIVES` (19 names) and `PATCHES` (`5`), opens the 19 archives, then `TPPS.PSARC` and `TPPS1.PSARC` to
  `TPPS<n>.PSARC`, `<n>` from `PATCHES`.
- It also tries `TPPS<n>-<LANGUAGE>.PSARC` for each update, and for three `.PATCH` names that no archive has, a loose
  file under `USRDIR`. Those are the failed opens in every log.
- So a translation can be a seventh update: `TPPS6.PSARC` with the two English text patches, and `PATCHES` holding
  `6`. That is how the official updates are made, so RPCS3 would read it as well.
- A translation takes English's place, with English voices. The game's languages follow the PS3's system language,
  which has no Indonesian, so a new one would need the title's code changed.

## The mod folder

`paths.mods` (`PS3_MODS_ROOT`) names a folder laid out like the PS3's paths: `dev_hdd0\game\NPUA80918\USRDIR\...`.

- A file there is read in place of the game's, or added where the game has none.
- Folders are not merged: a listing shows the game's.
- Empty, the default, there is no mod folder.
- The three path translators (`sys_fs`, `cellFs`, `ppu_fs`) ask it first. It is header-only
  (`runtime/syscalls/vfs_mods.h`), so the test fixtures that link one translator alone need nothing new;
  `test_vfs_mods` checks it.
- A guest path with `..` is never looked up there, and the log names each file taken from it, the first 64 times:
  `[fs] mod '<guest path>' -> '<file>'`.
- The problem report hides the folder's path, as it hides the others (`<mods>`).

## The test

A mod folder with `PATCHES` holding `6` and a `TPPS6.PSARC` of the two English patches, five entries changed: the
pause menu's title and four of its items (ids 1 to 5), one line each, into Indonesian. The text grew by 9 bytes, inside
the patch's padding.

Two runs of the Megaera fight on test saves, with the player's settings:

| run | pressed | the screenshots |
|---|---|---|
| 1 | START, ~46 s after the load | the upgrade menu, whose text was left as it was |
| 2 | SELECT, ~30 s after the load | the pause menu: its title and the four items in Indonesian |

- **The game took the text from the mod folder.** The log has `[fs] mod` for `PATCHES` and `TPPS6.PSARC`, and a
  failed open of `TPPS6-ENGLISH.PSARC` like the other updates'.
- **Nothing else changed.** "Controls" and the button hints stayed in English, as they were not touched. The font
  draws the text in capitals, as it does the English. The fight ran at 29.4 flips/s.
- **The buttons.** In this game START opens the upgrade menu and SELECT the pause menu.
- **The clocks.** `PAD_SCRIPT` times count from the first pad poll, about 2 s after the start; `gowa.py bench
  --shots` counts from the load, here at 49 s.

## The tool: `gowa.py text`

`scripts/gametext.py`, in the Kit's scripts too, as `gowa.py` imports it.

- **`export [--part story|mp|bonus|menus|all] [--context]`.** It reads the newest text patch of the game's folder
  and writes `build/text/en-<part>.tsv`, a line for each line of text: `<id>.<k><TAB><text>`.
  - `k` counts the entry's lines that have a letter. The subtitle cues, the `[[F:n]]` lines and lines of tokens alone
    stay out.
  - `--context` adds the line's sound as a third column, which tells who speaks and where.
- **`build <files>`.** It reads translations in the same form, as many lines as are done, then writes
  `build/mods/.../TPPS<n+1>.PSARC` with both patches, and `PATCHES`. It refuses, and writes nothing, for:
  - a line that drops or adds a `[..]` token;
  - an empty line, an unknown key, or a key twice;
  - a character the English never uses. Letters, digits and the space are always allowed; curly quotes, dashes and
    the ellipsis become ASCII.
- **What it gives.**

  | export | lines | entries | characters |
  |---|---|---|---|
  | story | 656 | 653 | 33,201 |
  | story, `--context` | 656 | 653 | 44,425 |
  | all | 8,852 | 4,948 | 488,007 |

  For the story, the text with its cues and ids is 48,722 characters; the export is a third smaller.
- **Checked against the game's files.**
  - A build with nothing translated gives `TPPS5`'s two patches byte for byte.
  - A build with the five lines of the test gives the `TPPS6.PSARC` tested in the game, byte for byte.
- **`tests/test_gametext.py`** checks both on a made-up game folder, in CI.
