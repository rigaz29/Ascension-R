# L2, before the work: what the interpreter still runs, and what lifting it needs

Measured on the port after the 3D scenes render (menu and the first level's opening scene), with
three new probes in the runtime:

- `SPU_DMA_RANGE_UNIQ=1` (with `SPU_DMA_RANGE=<lo>-<hi>`): each distinct `(ea, size, lsa)` of
  the transfers touching the range, once.
- `SPU_INTERP_BYSIG=<s>`: interpreted steps by the 16 bytes at each interpreter entry,
  exclusive of nested runs. Code that runs at a different local-store address each time adds
  up in one row, and the bytes find it in the executable.
- `SPU_INTERP_ENTRIES=<lo>-<hi>` (existing) with the code bytes at each entry.

## Where the interpreted steps are

About 40 M interpreted steps a second in both the menu and the level. Mapped to the
executable (`bysig_map.py`: entry bytes -> EA -> the GET that holds them), more than 99% is in
26 code fragments between EA `0x755080` and `0x766280`:

| `0x755B80` | 2368 | +0x20 | 2.0 | 11.1 |
| `0x758590` | 2144 | +0x90 | 1.8 | 7.7 |
| `0x75E180`, `0x75EB40` (same bytes) | 1248 | +0x14 | 9.2 | 5.9 |
| `0x75BD10` | 1552 | +0x20 | - | 5.5 |

Bigger streamed blocks (`0x718C30`, `0x7529B0`, `0x6EEE30`, `0x6F1730`, landing at LS
`0x16000-0x22000`) add up to about 0.5 M steps/s. About 35 interpreter entries fall inside
lifted job modules (owners 200-227): callback entries the module lifts lack, as in L1.

## How the fragments arrive and run

- Each is fetched whole by a GET (`cmd 0x41`) from its EA, by the job kernel (LS `0x2038`),
  into LS `0x11000-0x12400`, packed one after another; which ones a job takes varies, so each
  lands at 3 to 38 different addresses. About 3.4 MB/s of these GETs in the menu.
- Each has one entry, at a fixed offset from its start (the GET is 16-byte aligned, the code
  need not be). Job module 210 (LS `0x4000-0xF77C`, lifted) calls it with `bisl` (returns at
  `0x092F0`, `0x0D1E4`, `0x0DC5C`).
- Static survey of the 26 (`frag_static.py`): no `brsl`, `brasl`, `bra`, `bisl`, no branch that
  leaves the fragment, no computed `bi` (only `bi $0` returns), no channel instruction. The only
  placement-dependent instruction is `lqr` (228 in all), and every one reads the fragment's own
  constant pool at its end. `hbr`/`hbrr` are hints. The words decoded as `stop` are that pool.

So these are leaf kernels: entry, internal branches, PC-relative constant loads, return.

## What lifting them needs

Lifter (`spu_lifter.py`), a position-independent mode: functions read `ctx->pic_base` once at
entry; every LS code address the lifter writes as a constant becomes `pic_base + offset`
(`lqr`/`stqr` addresses, link values, `spu_drain_call` returns, `SPU_DIRECT` and `ctx->pc`
targets, external stubs). The EDGE fragments exercise only the first; the others matter for
the bigger blocks and are cheap to cover at the same time.

Runtime (`spu_channels.c`): a verified region that is not tied to one load address. A GET
from the fragment's EA marks a resident code slot at whatever LS address it landed; the first
dispatch compares the bytes there with the lifted ones (once per load); dispatch into the slot
looks the function up by `lsa - slot base` and sets `ctx->pic_base`; the dispatch cache keeps
the base with the function. Resident code slots 4 -> 16, overlay sources 128 -> 256 (a job
holds the module at `0x4000`, several fragments, and a block).

Tool: one lift per distinct fragment content (two EAs share bytes), a registration unit that
registers each source EA as a position-independent verified region. The list of fragments
(EA, size, entry) comes from the inventory above, kept in the port.

Not needed for the EDGE fragments: identification by content at the interpreter, scanning
bigger GETs for fragments. All the transfers seen here are whole-fragment GETs from the
fragment's own EA. A fragment that arrives any other way stays interpreted, as now.

## Order of work

1. Baseline: `SPURS_WID_PROF` on the EDGE workloads (14-16) and flips in menu and level.
2. Runtime position-independent regions, with a unit test (one lift, two placements, a stale
   placement rejected).
3. Lifter mode and the fragment tool; lift the 26.
4. Measure: interpreted steps (`SPU_INTERP_BYSIG`) should fall by about 99%, then EDGE time per
   run and flips; check the level's geometry as in the re-measurement.
5. The 35 job-module callback entries (`jobmods_extra.json`), then the bigger blocks if they
   still show.
