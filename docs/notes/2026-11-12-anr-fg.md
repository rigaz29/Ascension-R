# ANR FG in place of FSR's interpolation, experimental (2026-11-12)

- **What:** branch `exp/anr-fg`, here and in the fork. `[graphics] frame_generation = anr` has Apex Neural Rendering's
  frame generation (ANR FG, github.com/apex-compute/ANR, beta FG V.B14) make the generated frames, while FSR 3.1's
  frame generation swap chain presents and paces them as before. Only builds with `-D PORT_ANR=ON` have it (the fork's
  `PS3RECOMP_ANR`); no release is built with it.
- **Licences:** ANR is closed and comes with no licence, so its DLL is the player's own download: never kept here,
  never fetched by the program. The port talks to it through NVIDIA's DLSS-G (NGX) interface. NVIDIA's three NGX
  headers (NVIDIA RTX SDK license) are downloaded when the build is configured, from NVIDIA's DLSS repository at tag
  v310.9.16, checked against SHA-256, into `build\ps3recomp_sdk\ngx\include`; Windows' `curl.exe` fetches them, as the
  WinLibs CMake's own curl has no CA list to check GitHub's certificate with. Nothing of OptiScaler (GPL-3.0) or
  Streamline is used. Apex's `nr-replay`, which calls the DLL as a host, has no licence either: it was read for the
  order of the calls, and nothing was taken from it.
- **The calls** (`ps3recomp/libs/video/rsx_anr.cpp`): the DLL is loaded with `LoadLibraryEx` from `graphics.anr_dll`
  (`D3D12_ANR_DLL`; by default `anr\nvngx_dlssg.dll` beside the exe), and its own exports are called:
  `NVSDK_NGX_D3D12_Init_Ext` (application 1, the temp folder, the device, no common info), `PopulateParameters_Impl`
  into our parameter map (it gives `MultiFrameCountMax` 5), `CreateFeature(FrameGeneration)` at the first generated
  frame, and one `EvaluateFeature` a frame with `MultiFrameCount` 1. The map is ours, an `NVSDK_NGX_Parameter` with
  its virtual `Set` and `Get`: NGX's values carry no type, so a number reads back as whichever type is asked for.
- **Where:** FSR's swap chain asks for the generated frame through `frameGenerationCallback`. In the FidelityFX SDK
  1.1.4 source (`dispatchInterpolationCommands`) that happens inside its `Present`, on the thread that presents, ours,
  and without async workloads the callback's command list runs on the game's queue right after the frame's. So ANR is
  called from the callback (`fsr3_anr_generate` in `rsx_fsr3.cpp`) with the swap chain's backbuffer, in PRESENT, and
  its output, in UNORDERED_ACCESS, while the frame's depth, motion and picture without its HUD are still as the frame
  left them: no copies of them are kept. FSR's own prepare pass is skipped; its context stays, for the swap chain.
- **States and parameters:** the textures go in the states DLSS-G hosts give them (nr-replay's README): the backbuffer
  NON_PIXEL_SHADER_RESOURCE; the HUD-less picture, depth and motion COPY_DEST; the outputs UNORDERED_ACCESS. The
  parameters are the ones OptiScaler gave ANR in the test of 2026-11-12 (ANR's log prints them), with the port's own
  camera: `MvecScale` the render's size (the motion is in UV units, as FSR takes it); `MvecInvalidValue` FLT_MAX
  (unset, ANR read 0, which a still pixel holds); the jitter in pixels; near, far, the vertical field of view, the
  aspect; the camera's position and axes from the view-projection; the projection made from those (right-handed, by
  rows, the point a row) and its inverse; FLT_MAX for the clip-to-clip matrices; depth and motion subrects at the
  render's size. `OutputReal`, which ANR fills with a copy of the backbuffer, is a texture of ours that nothing reads.
  `D3D12_ANR_CAMERA=0` gives ANR a camera that never moves, as OptiScaler did.
- **Resets and failures:** a frame with nothing before it (FSR's reset, a cut, a new feature) and a failed evaluation
  show the real frame twice: it is copied into the output. When the feature cannot be made or ten evaluations fail in a
  row, FSR's own frame generation takes over from the next frame, from a reset. A resize releases the feature with FSR's
  context, and the next generated frame makes it again.
- **Measured:** issue #7's session replayed to the Grotto with copies of its saves, 1920x1080 from 1280x720, GTX 1650
  Ti, a 60 Hz display on the AMD iGPU, 30 s of the screen recorded 40 s into the level; the same exe for A and C.

  | | FSR 3.1 FG | ANR, from the port | ANR through OptiScaler |
  |---|---|---|---|
  | Runs | A2, A3, A4 | C1, C2 | B2, B3 |
  | Real frames a second | 30.0 | 30.0 | 30.0 |
  | Frames shown a second | 59.8 to 59.9 | 59.8, 59.9 | 59.9, 59.0 |
  | A frame held for two refreshes, in 30 s | 2, 2, 2 | 2, 2 | 2, 26 |
  | ANR's GPU time per real frame | | 4.2 ms | 4.1 ms |
  | ANR's evaluate CPU and interop, p99 | | 0.6 and 0.3 ms | 0.8 to 1.3 and 0.4 to 0.7 ms |

  In the frames, FSR's generated ones tear and double Kratos' legs and boots as he runs; ANR's keep him whole. 3000
  frames generated a run, none failed. Windows' GPU engine counters gave 56 to 64% for the 3D engine with no pattern
  between the runs; ANR's own timings are the ones to go by.
- **Measuring the cadence:** ffmpeg's ddagrab takes the screen every 8.3 ms (120 Hz) and the display shows a frame
  every 16.7 ms, so intervals of 8 and 25 ms in a recording are the polls' phase against the refresh: each such pair adds
  up to 33.3 ms. Their spread says nothing of the pacing (FSR alone: 1.6 to 6.5 ms between runs; the 2026-11-12 A/B
  read it as ANR through OptiScaler pacing worse, wrongly). What counts on a 60 Hz display is a frame held for two
  refreshes, an interval of 29 ms or more, and the frames shown a second.
- **Not tried yet:** a display over 60 Hz or with VRR, where pacing shows more; input latency; resizing or full screen
  while it runs; AMD and Intel GPUs; the launcher, whose Frame generation switch shows off for `anr` and writes on or
  off when switched.
- **To try:** `py scripts/gowa.py build -D PORT_ANR=ON`. From ANR FG's release zip (`anr-fg-V.B14-full` or
  `-addon`), the folder that holds `nvngx_dlssg.dll` (`OptiScaler\custom\Apex Neural Rendering FG\dlssg`) copied to
  `build\anr\`; the DLL writes its logs and a copy of the system's `vulkan-1.dll` there, so a folder the user can write
  to. Then `frame_generation = anr`. The game's log has `[anr]` lines; ANR's own is `nr_fg-*.log` in that folder.
